# Portfolio Memory

1. Read `../../../memory/PORTFOLIO_INDEX.md`.
2. Select only the relevant project capsule or capsules.
3. Read those capsule files; do not bulk-load every capsule.
4. Use them to recover purpose, boundaries, canonical pointers and likely current gate.
5. For current or consequential claims/actions, inspect the actual repository evidence before acting.
6. After a verified material milestone or durable decision, update that project's capsule and index only if needed.
7. Keep memory concise. Do not store logs, whole issue bodies, chat transcripts, secrets, credentials, or temporary debugging details.
8. If memory conflicts with repository/canonical project docs, current evidence wins and memory should be corrected.

Memory optimizes retrieval, not truth: it tells the agent where to look; current evidence tells the agent what is true.
